## Observations (not FAILs; no product or checklist change made)

1. **Byte-compiled files from bundled data.** The wheel contains no `.pyc` files, but
   `pip install` byte-compiled the bundled `_data` Python files at install time (32 `.pyc`
   files under `site-packages/tantular_cyber/_data/`, including the sample and the corpus
   cases). `tantular-cyber sample` then copied `__pycache__/app.cpython-311.pyc` into the
   sample directory. Compiling does not execute the code, and the benchmark corpus hash is
   unchanged (C2). Still, the sample a user receives includes a stray compiled file, and the
   deliberately vulnerable files get compiled on install. Candidate for a separate issue,
   for example: `sample` ignores `__pycache__`, and the docs suggest
   `pip install --no-compile`, or the data is shipped in a form pip does not compile.
2. Issues #17 (generic reason for a cloud-model refusal) and #18 (port redacted in
   `llm.endpoint`) were reproduced as filed. The #18 behaviour is visible in B6. #17 was not
   exercised, because B4 was blocked.
3. A3: `gh attestation verify` prints nothing in text mode without a terminal. A future
   checklist version could specify `--format json` for the retained evidence.
